# Long-horizon behavioral extension — design only, not executed

The first released case is a deterministic harness diagnosis. No compaction,
goal-drift, 20/50/100-step behavioral result is claimed. The higher-priority
behavioral research remains an explicitly unexecuted protocol, not a failure card.

A realistic future task can refactor a synthetic multi-module package while
preserving its public API and a protected configuration file. Fix tests, then
introduce successive maintenance requests, external repository-state changes,
and a documented compaction/resume transition. Define API signatures, forbidden
file hashes, required test commands, and final checkout correctness before runs.

For each horizon use at least ten independent real model executions. Compare
no-compaction with compaction at the same state, then compaction plus explicit
constraint restatement, compaction plus repository instructions, and a shorter
task. Match the model, tools, config, fixture commit, and task; record actual
compaction events rather than inferring them from context size. Retain failures
and interrupted runs with a predeclared denominator rule. Estimate frequency
and interval, not an unsupported global capability score.

Such executions require an available model/account, explicit usage budget and
privacy controls. None were run in this release. Deterministic protocol replay
results cannot substitute for these behavioral experiments.
