# Responsible disclosure and follow-up

At most one formal issue is filed for this project. No upstream code PR is
created. The selected issue focuses on an initialized resource-supporting
server returning a valid internal error, not a tools-only server or a
deliberately adversarial prompt.

Security issues follow [SECURITY.md](https://github.com/openai/codex/blob/main/SECURITY.md)
and OpenAI's private reporting process, never a public issue or exploit.

Maintainer replies receive concise evidence-based follow-up: rerun the original
fixture on the requested version, attach the minimal redacted result, and state
what changed. A duplicate decision is accepted; useful evidence may be supplied
to the canonical issue if appropriate. A fix is marked verified only after the
original reproduction passes on the stated release. No employee mentions,
job-search text, unsupported credit, or repeated status comments are posted.
